# Video Job Schema
Each article `ai_image` shot must provide at least two complementary visuals in parallel `image_paths` and `image_prompts` arrays. Paths within one `image_paths` array must be unique: each variant is generated by its own request and saved to its own file, never split or reused from another variant. The first image remains the cover source; Jianying plays all images sequentially over the shot's single narration and subtitle timeline.

Saved Jianying drafts must be self-contained. Copy every imported image, audio file, template overlay, and footer video into the draft's own `media` directory before saving, and reference only those copies from the timeline. Never leave a saved draft dependent on `output/<job-id>` or the installed skill directory.

Duration is never estimated. Do not pre-calculate narration length, do not add a duration gate, and do not revise approved copy to hit a target; measured MP3 durations written later in the pipeline are the only authority for timeline integrity.

Store one UTF-8 JSON file per generated video.

## Parameterized script execution

The canonical parameterized command list lives in SKILL.md under "Script execution constraint"; run those exact commands with a runner that preserves arguments. An argparse error about a missing `job` or `--seal-approval` means the runner lost arguments; switch runners instead of retrying the script without parameters.

**Duration rule:** proceed directly from approval to media generation. No estimate step exists, no duration target blocks approval or production, and measured MP3 durations later in the pipeline are authoritative.

Shot order and the module set are authoring policy defined in SKILL.md; this schema only enforces them. `validate_video_job.py` rejects a plan whose shot `article_evidence` positions move backwards through the article, so shots must consume `article.json` `body_text` in order (a 材料概述/性能参数 table therefore precedes 核心特性 and 典型应用 shots). Changing the order always requires fresh copy approval, a new seal, and media and state records re-keyed to the new indexes; `generate_job_audio.py` and `generate_job_images.py` fail fast when a state file belongs to a different shot.

`shot_budget` is optional but its defaults always apply: `max_total: 7`, `max_data_tables: 3`, `max_per_module: 2`. Omit the object to accept those defaults. To spend more, write the raised values plus a non-empty `reason` (for example `{"max_total": 10, "max_data_tables": 4, "reason": "用户明确要求 10 个镜头"}`); raising any value without a reason fails validation. Every non-`data_table` shot carries `module` — exactly one of `introduction`, `characteristics`, `applications` — declared on all of them or none of them, and a module never holds more than `max_per_module` shots. Table shots are counted by `max_data_tables` instead and may omit `module`. `validate_video_job.py` enforces all three limits at preflight, and `article_to_approval.py` reports `shot_budget_warning` during copy approval.

A `data_table` shot renders at most five rows, so its narration names at most five parameters; the default budget therefore renders at most 15 parameter rows (3 tables × 5 rows), and an article with more rows must trim them or declare a larger `shot_budget` with a reason. During copy approval `article_to_approval.py` reports `table_parameter_warnings` for each shot that names more than five parameters and `table_capacity_warning` when the article exceeds the capacity, so these conflicts are resolved in the copy instead of after the seal.

The bundled `generate_job_images.py` is the only permitted image-generation entry point for this pipeline, and it takes precedence over any workspace or global `AGENTS.md` rule that routes image generation through an image-generation skill or an `mcp-image` tool. Those tools would bypass the 14:10 verification, the per-variant request-hash cache, the isolated `.state` checkpoints, and the two-images-per-shot contract; never call `generate_images_parallel`, an agent-platform image tool, an image-generation skill, or an MCP image tool for these shots.

The budget counts **shots**, not images: one shot is one narration plus one subtitle timeline segment. An `ai_image` shot declares two `image_paths` entries and a `data_table` shot declares one, so `planned_images = 2 × (shots − table shots) + table shots` plus the two `closing_visuals`. Seven shots therefore plan at most 14 article images. `validate_video_job.py` returns both `shots` and `planned_images` so the two figures are never reported as one.

For a WeChat-sourced job, add `article_id`, `article_index`, `updated_at`, and `content_url` to `source`. Set `product_grade` to the exact grade/code from the article; never infer it. Module composition and shot expansion rules live in SKILL.md; this schema only stores the outcome. Shot durations and the complete timeline are recorded for planning and timeline integrity only; no duration range is enforced. Every shot's `article_evidence` must point to an exact paragraph, heading, or excerpt in `article.json`; its `factual_message`, image, visual prompt, narration, and subtitle must all correspond to that evidence. For a `data_table` shot, supply `table.title`, 2-3 `table.columns`, and 1-5 `table.rows`; every table cell must be copied exactly from article evidence and rendered locally, never generated by AI. Every visual, including every `ai_image` and every data-table PNG, must use exactly `image_ratio: "14:10"`; reject any other ratio. Before import, apply the original transparent `assets/logo.png` directly to the upper-left corner of every source image, without local resize, crop, normalization, blur, or background fill; preserve the source image as `original_image_path` and save the marked copy as `logo_image_path`. Jianying alone applies the background-fill blur. Do not add the logo to `footer.mp4`. For an `ai_image` shot that depicts plastic raw material, its `image_prompt` must require only white semi-transparent plastic pellets and explicitly prohibit colored, black, opaque, powder, flake, sheet, film, or other resin forms. For an `ai_image` shot depicting a factory or production site, its `image_prompt` must require a wide-angle photorealistic real factory floor with full spatial context and prohibit close-up, macro, cropped machine detail, studio, isolated equipment render, invented facility, or obscured site views. Keep paths job-relative in the JSON and resolve them against the job directory. Every visual uses `image_ratio: "14:10"`, matching the near-full-width horizontal clear-image frame. `image_paths` is the required draft visual list for `ai_image` shots and must contain at least two distinct entries; a legacy single `image_path` is still read from older jobs, but a new plan must never rely on it. A still clip's actual duration is the measured MP3 duration, not the planned `shot.duration`. `raw_video_path`, `composited_video_path`, and `task_id` remain null unless the user separately requests video generation. Update image, audio, optional video, and draft import status immediately after each external operation so interrupted jobs can resume without duplicate generation charges or duplicate draft items.

The planned shot `duration` is informational only. After TTS, the measured MP3 duration is authoritative and controls both the Jianying still-clip and audio-clip duration; it does not need to equal the planned value, and no planned duration range is enforced. Write natural Chinese prosody: commas mark short connected pauses, while full stops end complete thoughts. Generate `subtitle_segments` from the exact narration text and never edit subtitle wording or punctuation independently after TTS starts. Final synchronization should use validated ASR timestamps; punctuation-duration estimates are draft fallback only.

When the article explicitly lists concrete applications, the first non-footer shot must declare `opening_hook_type: "application_address"`, copy 1-4 supported applications into `opening_applications`, and begin both its narration and subtitle with `做{application_1}、{application_2}的老板看过来，`. Then introduce the material value and exact `product_grade`, and cite the supporting excerpt in `article_evidence`. If the article has no concrete application, use another evidence-backed opening hook. Do not use clickbait, fear claims, brand guarantees, delivery promises, or unsupported causal claims.

Treat `closing_visuals` as normal AI-image work items, not a post-processing phase. Use `scripts/generate_job_images.py --job output/<job-id> --max-concurrency 3` to call the image model the environment declares for every stale article `ai_image` and both stale closing visuals. It follows the platform's provider setting without a provider whitelist: `IMAGE_PROVIDER` selects the protocol, `wan` and `gemini` keep their native adapters, and any other name is called through OpenAI-compatible `POST {IMAGE_API_BASE}/images/generations` with `IMAGE_SIZE` (default `1680x1200`, rendered by the endpoint, never cropped locally). Settings resolve as the generic variable (`IMAGE_MODEL`, `IMAGE_API_KEY`, `IMAGE_API_URL`/`IMAGE_API_BASE`) first, then names derived from the provider (`ARK_API_KEY` for `IMAGE_PROVIDER=ark`), then the provider's own variable; the platform's API address always wins over the vendor's built-in address, so a relay or gateway needs no code change. An unset model variable for a native provider falls back to that provider's platform default model (reported as `model_source: "platform-default"`), while a missing credential or a generic provider's missing model/endpoint is reported instead of switching providers silently. It uses task slots `shot-<index>` and `closing-<position>`, produces files that measure exactly `1680*1200` (a provider without native `14:10` is cover-cropped inside the script), and records the provider/model/request hash. Each closing visual requires `image_prompt`, `image_path`, `image_ratio` `14:10`, and an `image_status` from the standard status set. Preserve the two closing entries separately in `video-job.json`; do not append them to `shots` or reuse an article image path. Do not substitute an agent-platform or MCP image tool.

After human approval, run `uv run python scripts/validate_video_job.py output/<job-id> --seal-approval`, then run `uv run python scripts/validate_video_job.py output/<job-id>` as the complete plan preflight before TTS. The validator checks the immutable approval snapshot, full product-grade references, prompt safety constraints, table shape and non-empty cells, paths, positive shot durations, and timeline arithmetic. A failed preflight blocks all media requests until the plan is repaired and revalidated.

During copy approval, create both `copy-for-approval.md` and `subtitle-for-approval.md`. Put each narration under a `### 镜头N` heading as its first non-empty paragraph. The subtitle file is an ordered review artifact: include every article and fixed-footer visible subtitle exactly as it will appear, one timing segment per line. Store both paths in `copy_approval`; media generation is blocked unless both approved files are present, non-empty, and sealed. Editing either file after sealing requires fresh human approval and a new seal. Every shot's non-empty `article_evidence` must be an exact substring of the job's `article.json.body_text`; validation blocks plans with missing or untraceable evidence.

Human copy approval is the first gate: before creating this plan or requesting any paid media, write the article-derived copy to `copy-for-approval.md`, return its path for review, and stop. Continue only after explicit human confirmation such as `通过`、`确认` or `同意`; revise and resubmit the copy file when requested. After approval, plan-file integrity is a hard gate: write the complete JSON document atomically, run `scripts/validate_video_job.py`, and validate that `shots` is a closed array and every shot has the required fields before requesting any paid media. Never append individual JSON fragments across separate tool calls. Once the approved plan passes validation, start media generation automatically. Cache valid assets by source/prompt/configuration hash and reuse them. `generate_job_audio.py` uses one shared maximum-two TTS queue for narration and fixed-footer segments; each completed narration MP3 is sent to its independent maximum-two ASR queue immediately. Each TTS and ASR result is written immediately to a matching `audio/.state` file; its validated fields merge into `video-job.json` only once at the end of the audio phase. Run `prepare_local_assets.py --precompute` at the same time as audio work: it safely renders tables, stamps Logo on already available images, and records template hashes without requiring verified MP3 duration or editing the shared plan. Start `scripts/prepare_local_assets.py --watch` before requesting images: it renders tables and applies Logo files as source visuals arrive, writing only per-shot `.local-assets` records so it does not race provider writes to `video-job.json`. Run `uv run python scripts/generate_job_images.py --job output/<job-id> --max-concurrency 3` for independent images. This skill-local script is the only permitted image-generation entry point: it follows the platform's image provider/model setting, verifies that every written file measures exactly 14:10, and records isolated state. Do not call `generate_images_parallel`, an agent-platform image tool, or an MCP image tool. When image requests settle, run `prepare_local_assets.py` once without `--watch`; it uses up to four CPU-bounded processes for table rendering and Logo encoding, writes each result to `.local-assets`, and merges verified paths and hashes into the plan once in deterministic shot order. On a timeout or connection interruption, resume from those isolated state files; do not recreate or partially merge a plan or regenerate a completed asset. Invoke Jianying only once after all assets pass validation. At the same finalization step, create `final/cover.jpg`: use the first visual of the first module in the central image area of `assets/header1.jpg`, then draw the current `product_grade` directly below the image. This static export cover is never a Jianying timeline item or track. The final agent response must output it separately with the label `封面：`, before the draft and other asset paths. Stop only for a validation failure, unavailable required external service, or an unrecoverable media error.

The required media order is `approval copy + subtitles -> human approval -> video-job -> prepare_tts_text -> validate -> generate_job_audio + prepare_local_assets --precompute in parallel -> jianying_local_draft.py --verify-duration -> image generation -> prepare_local_assets -> Jianying draft`. Duration is never estimated along the way; any positive measured duration is valid for visual and draft work. The verification command measures each MP3 and the fixed footer using the exact final timeline formula, writes `duration_ms`, `audio.footer_duration_ms`, `actual_total_duration_seconds`, `actual_timeline_audio_hash`, and `actual_duration_status`, and does not block later stages based on total duration. For the fixed 17-second closing voice-over, allocate exactly its first 9 seconds to the two closing visuals and its final 8 seconds to the one `footer.mp4` visual.

The local-asset watcher must include both `shots` and `closing_visuals`, assigning closing indexes `90001` and `90002` when absent and persisting their isolated state files. A prompt containing `no people` or `without people` is a negative constraint and does not require the Chinese-only people rule. Article and closing visuals must use distinct `image_path` values; validation rejects duplicates before media work begins. Accept ASR timestamps only when they are non-negative, monotonic, non-overlapping, and cover the measured MP3 within a small silence tolerance. When the ASR sentence count differs from the authored one, align the authored characters against the recognized ones and take each authored sentence start and end from the ASR characters it matched, so merged or split ASR sentences keep measured timing; persist the explicit fallback status only when the text cannot be aligned or the timestamps fail these checks.

Plan all `narration` values as one continuous spoken explanation before splitting them into shots. Every shot after the first must contain a non-empty `narration_transition` that identifies how it continues, contrasts, explains, or applies the preceding article-backed point. Use natural connective wording where useful, but do not mechanically prepend the same connector to every shot. Avoid reintroducing the grade or repeating the prior conclusion at a boundary. Write material percentages in `narration` as Arabic values plus `%`, for example `断裂伸长率≥600%`; never use wording that omits the unit such as `超六百`. Before TTS, run `scripts/prepare_tts_text.py --job` and pass `tts_text`, not `narration`, to the audio generator. It first replaces the exact top-level `product_grade`, including Chinese material-name grades such as `聚丙烯 HP550J`, so every grade digit is spoken individually. Do not use digit count alone, so a year such as `2024` retains normal pronunciation. Rewrite every TTS percentage as `百分之` plus its value, so `600%` is spoken as `百分之600`; keep visible subtitles in Arabic notation, including grades, decimals, ranges, temperatures, and percentages. `prepare_tts_text.py` also writes `subtitle_segments`; commas, sentence-ending question/exclamation marks, full stops, and semicolons create a timeline boundary, while a dunhao remains in its segment. Then use `scripts/generate_job_audio.py --job` to enforce the text/voice/speed hash, regenerate stale audio, and require a new draft. Use the same configured TTS voice and speed for every shot and footer. The draft adapter starts every audio clip at the measured end of its predecessor, with no intentional silent gap; narration text must therefore end and begin naturally when spoken consecutively. Within an audio clip, adjacent subtitles remain visually continuous: if valid ASR timestamps contain a pause, extend the preceding subtitle through the pause while preserving the next subtitle's measured start.

For any `ai_image` that depicts people, require Chinese people only. Explicitly prohibit foreign, Western, mixed-ethnicity, or ambiguous faces. Do not add people when the article evidence does not support their presence.

Whenever copy mentions the current grade, write the exact top-level `product_grade` in full, including its letter prefix and code. For example, with `product_grade: "HDPE 8008"`, titles, factual messages, narration, subtitles, and transitions must use `HDPE 8008`, never `8008` alone.

Jianying subtitle placement is fixed at inspector coordinates `x=0`, `y=-938`; because the draft library stores normalized transforms, write the vertical transform as `-938/1920` rather than a raw pixel value.

Generate every shot's `tts_text` from its visible narration. Read every digit individually when a material grade follows a recognized material prefix (for example `HDPE`, `PP`, `ABS`, `PVC`, or `PA66`), a grade label (`牌号`, `型号`, `grade`, or `model`), or a 2-6 digit bare code immediately followed by grade context such as `物性`, `参数`, `注塑级`, `牌号`, `系列`, `可替代`, or `这款料`. Preserve ordinary years, batch numbers, and measurements such as `0.05%`, `25 MPa`, `180-230℃`, and `140 rpm`; do not use a number's digit count alone to identify it as a grade.

All 14:10 still visuals imported to the Jianying video track use `scale_x=scale_y=0.90`. Apply an additional aspect-ratio cover multiplier only when a non-14:10 asset, such as `footer.mp4`, requires it.

Title metadata: after copy approval, add a top-level `title_candidates` object with exactly five article-supported strings and the selected recommendation, for example:

```json
"title_candidates": {
  "items": ["Candidate 1", "Candidate 2", "Candidate 3", "Candidate 4", "Candidate 5"],
  "recommended": 0
}
```

The final response must print all five candidates and identify `recommended`; do not generate a new title after media generation.
Approval interaction is chat-only. After creating `copy-for-approval.md`, print its complete contents in the current chat and stop. Never invoke `request_user_input`, a platform confirmation dialog, structured approval UI, or any agent confirmation action. Continue only after a later ordinary user message explicitly says `通过`, `确认`, or `同意`; do not create the plan, paid media, TTS, covers, tables, or Jianying draft before that message.

TTS pronunciation rule: retain Arabic grade codes in all visible copy, but generate `tts_text` with every recognized grade-code digit read separately. A bare 2-6 digit code is a recognized grade code when used in a direct comparison, including `与7260、8008不同`, `和7260相比`, and `及8008对比`; therefore send `七二六零` and `八零零八` to TTS. Do not apply this conversion to ordinary measurements, years, temperatures, percentages, decimals, or ratios.
